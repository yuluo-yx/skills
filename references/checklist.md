# 中文文档交付前自检清单

新建或整篇改写检查全文；局部修改只检查涉及的范围，校对不借自检扩大改动。先检查事实与授权范围，再检查结构和排版。

## 范围与事实保真

- 是否按撰写、改写、校对或审阅模式交付，没有擅自扩大修改范围。
- 是否遵守目标项目约定，没有把本技能的示例当成项目规则。
- 是否新增来源没有提供的数字、年份、日期、时限、SLA、能力或因果结论。
- 前置条件、例外、风险、兼容性、法律含义、单位、默认值和失败处理是否保留。
- 主语、对象、否定范围、因果关系和确定程度是否与来源一致。
- 信息缺口是否具体说明，没有靠补造事实形成完整稿。
- 代码、路径、字段、命令、枚举、配置、链接目标与固定引用是否保持原样。

## 结构

- 标题层级是否连续，没有从一级直接跳到三级。
- 是否存在「只有一个子标题」的孤立层级。
- 标题是否准确概括内容，没有标题党或口号式表达。
- 文档结构是否符合文档类型，必要章节是否齐全。

## 段落与句子

- 每个段落是否只有一个主题。
- 段首是否有中心句。
- 是否按主题分段，中文 Markdown 正文是否保持一段一行，没有按屏幕行数硬拆段落。
- 句子是否过长，是否可以拆成简单句或并列句。
- 被动语态或否定是否造成歧义，修正是否仍保留必要条件与禁止关系。
- 代词指代是否清楚。

## 术语与风格

- 同一概念是否使用同一术语，不混用别名。
- 英文缩写首次出现时，是否给出必要解释。
- 专有名词大小写是否正确。
- 「的、地、得」使用是否明显错误。

## 数字与排版

- 中文与英文、中文与数字之间的空格策略是否统一。
- 数字是否使用半角形式。
- 千位分隔是否只用于适用的正文数值，没有误改年份、端口或标识符。
- 单位、时间、范围、百分比、货币写法是否统一。
- 新建文件名是否符合项目约定，没有为排版擅自重命名已有文件。
- 百分比与百分点、范围上下界、数值精度和已知时区是否准确。
- 代码、表格、引用和显式换行是否保持结构，链接与行内代码外侧留白是否正确。

## 标点

- 中文句子是否统一使用全角标点。
- 标题末尾是否误用了句号、逗号、冒号等点号。
- 中文并列项是否使用顿号。
- 引号是否遵守项目约定或默认的 `「」`、`『』`，省略号是否使用 `……`，没有改动固定引用。
- 是否误用了多个感叹号或非正式标点。

## 引用与事实

- 直接引用、转载、图片是否标明来源。
- 技术结论、版本行为、参数限制是否有来源支撑。
- 链接是否可读、标题是否准确、引用对象是否最新。

## 按内容类型检查

- API 参数是否说明已知的类型、必填性、单位、默认值、范围和依赖，没有修改字段名或枚举值。
- HTTP、业务、任务状态是否区分，「已受理」是否被误写成「已完成」。
- 错误提示是否给出有依据的问题、影响和恢复操作，没有猜测确定原因或恢复时间。
- 操作步骤是否先交代条件与风险，区分人工动作和系统行为，保留停止条件与恢复方式。
- 界面空状态是否区分无数据、尚未创建、无权限与加载失败，危险操作是否说明后果。

## 最终判断

如果下面三个问题都能回答「是」，通常说明文档可以交付：

1. 不看上下文，读者能否按文档完成操作？
2. 快速扫读标题和段首，是否已经能理解全文结构？
3. 删除华丽修辞后，文档是否仍然完整、准确、清楚？
