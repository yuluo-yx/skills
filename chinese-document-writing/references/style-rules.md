# 中文文档风格规则

仅在处理结构、措辞、术语或排版细节时读取对应章节。规则作用于可编辑的可见正文；代码、路径、字段、命令、配置、链接目标、固定引用和用户指定字面量保持原样。来源与融合范围见 [来源说明](sources.md)。

## 1. 标题

- 标题最多使用四级，常规文档尽量控制在三级以内。
- 一级标题下不能直接出现三级标题，层级必须连续。
- 避免孤立编号；如果某一级只有一个子标题，通常应收拢结构。
- 下级标题不要重复上级标题名称。
- 标题末尾不加句号、逗号、顿号、分号、冒号。

推荐：

```markdown
# 安装指南

## 环境要求

## 安装步骤

### macOS

### Linux
```

## 2. 文档结构

对较完整的软件文档，优先采用下列结构进行取舍：

- 简介：说明产品定位、目标读者、文档范围。
- 快速上手：给出最短使用路径。
- 入门篇：环境准备、安装、设置、基础用法。
- 进阶篇：高级场景、开发扩展、性能与调优。
- API：接口、参数、返回值、错误说明。
- FAQ：常见问题。
- 附录：术语表、最佳实践、故障处理、版本说明、反馈方式。

新建文档文件名默认遵守以下规则，目标项目约定可以覆盖；不得仅为风格统一重命名已有文件或破坏引用：

- 不含空格。
- 使用半角字符，不使用中文文件名。
- 默认小写。
- 多词之间用 `-` 分隔。
- 特例文件可使用 `README`、`LICENSE` 等惯例大写名。

## 3. 句子与措辞

- 优先保持清晰的句子主干；条件、动作和例外过多时拆分，不用固定字数作为合格门槛。
- 优先使用简单句和并列句，少用多层嵌套的复合句。
- 优先使用肯定句，必要的禁止、否定范围和例外保持准确；不要为了形式消除否定。
- 优先使用主动语态，执行者未知或被动表达更准确时保留原意。
- 使用现代汉语常用表达，不用生造词、文言词或过度书面化表达。
- 代词必须指代明确，避免「其」「该」「此」指向不清。
- 名词前不要堆叠过多形容词。
- 默认不直接称呼读者；必要时写明角色。品牌规范或界面语境可以允许第二人称。
- 删除没有实际含义的「赋能」「抓手」「闭环」「拉通」等表达，写出具体能力、措施或流程；正式术语、固定引用和用户要求保留的内容除外。
- 「场景」「链路」「路径」「输出」等词可能有技术含义，只按语境判断，不全局替换。

改写方向：

- 不清楚的句子改为「主语 + 动作 + 结果」。
- 复杂说明改为「前置条件 + 操作步骤 + 输出结果」。
- 抽象描述改为可执行表述。

## 4. 段落

- 一个段落只表达一个主题。
- 中心句放在段首，后文围绕中心句展开。
- 不按屏幕行数判断段落长度；主题发生变化或条件堆叠时分段。
- 段落之间空一行。
- 段首不空两格，不插入无意义缩进。
- 叙述语气保持平实，避免口号式表达，不改变事实的确定程度。
- 中文 Markdown 正文一段一行，不按源文件行宽硬换行；保留列表层级、代码块、表格、HTML 块、引用块、链接引用定义和显式换行。
- 合并硬换行时逐处检查边界：中文接中文不添空格，中文接英文或数字留一个半角空格，全角标点两侧不添空格。

## 5. 中英文、数字与空格

- 可见正文中的中文与英文单词、缩写、阿拉伯数字、版本号之间留一个半角空格，如「使用 API」「等待 3 秒」「版本 2.0 已发布」。不拆开官方产品名或固定字面量。
- 中文与行内代码之间留一个半角空格，只调整代码标记外侧；紧邻全角标点时不加空格。
- 链接按显示文字判断留白，不在 Markdown 链接语法内部插入空格，不修改链接目标。
- 半角英文或数字与中文全角标点之间不留空格。
- 阿拉伯数字一律使用半角数字。
- 较大的普通计数按项目约定使用千位分隔符，如 `12,500`；年份、端口、版本、标识符和机器可读数值不添加分隔符。
- 货币写法用阿拉伯数字，并在前面加货币符号或后面写中文货币名称，如 `$1,000`、`1,000 美元`。
- 普通中文中的范围优先使用「至」，如「3 至 5 天」「67% 至 89%」；保留上下界、单位和是否包含边界的含义。
- 表示变化时区分「增加了」和「增加到」、「降低了」和「降低到」。
- 「降低 N 倍」含义不清时先确认基数和测量口径，不自行推断百分比。
- 区分百分比和百分点：从 20% 增长到 30%，增加 10 个百分点，相对增长 50%；没有基数时不自行换算。
- 数字与英文单位留空格，如 `200 ms`、`25 °C`；百分号和角度符号紧邻数字，如 `50%`、`90°`。
- 不因排版改变数值精度、换算单位或补全日期。跨时区信息只注明已知时区，缺失时说明缺口，不按所在地猜测。

## 6. 标点

- 中文句子使用全角标点。
- 整句英文使用半角标点。
- 句号、逗号、顿号、分号、冒号等点号不得出现在标题末尾。
- 逗号不要“一逗到底”。
- 中文并列项使用顿号 `、`，最后一项可用“和”连接。
- 中文正文默认使用直角引号 `「」`，嵌套引用使用 `『』`；项目、地区、出版和固定引用规范可以覆盖。
- 补充说明使用全角圆括号 `（）`，括号前后不加空格。
- 说明列表前使用全角冒号 `：`；时间写法用半角冒号，如 `8:00`。
- 中文省略号使用 `……`，破折号使用 `——`；代码、命令选项和 Markdown 标记保持原样。
- 避免使用感叹号，更不要连用多个感叹号。
- 连接复合名词或图表编号时用半角连字符 `-`，如 `图 1-1`。
- 完整句式的列表项使用句号，短语项可不加句号；同一列表保持一致。

## 7. 英文与专有名词

- 英文首次出现时，必要时给出中文说明或中英文对照。
- 后续再出现时可直接使用统一缩写。
- 专有名词使用正确大小写；普通名词不要随意首字母大写。
- 英文省略号翻成可编辑的中文正文时改为 `……`，固定引用除外。
- 英文作品名翻成中文时，用书名号《》。
- 英文复数翻成中文时，通常还原为单数概念表达。
- 常见写法包括 `API`、`HTTP`、`URL`、`JSON`、`JavaScript`、`TypeScript`、`Node.js`、`GitHub`、`PostgreSQL`、`gRPC` 和 `GraphQL`；只调整正文，不改同名代码标识符。
- `OAuth` 不自动补成 `OAuth 2.0`，`H5` 不直接替换成 `HTML5`，`Postgres` 是否改成 `PostgreSQL` 由项目正式命名决定。

## 8. 错词与语境

- 明确错词可修正，如「阀值」改为「阈值」、「布署」改为「部署」、「反回」改为「返回」、「回朔」改为「回溯」。
- 语境词只在含义明确时修正：登录系统与登陆月球、配置参数与配制溶液、截至某日与截止日期。
- 区分认证与授权：认证确认身份，授权授予权限。
- 不把含糊期限、倍数和能力改成精确承诺。例如「尽快处理」不能补成「30 分钟内处理」，「可能失败」不能改成「会失败」。

## 9. 引用与来源

- 直接引用第三方内容时标明作者与来源。
- 整篇转载需在文首显著位置说明出处并链接原文。
- 外部图片需在图下注或文末标注来源。
- 技术参数、版本行为、标准规范等信息，优先附上官方链接或文档来源。

## 10. 检查边界

自动检查只用于确定错字、明确的术语大小写和受保护内容的差异。句长、被动句、代词、黑话、条件顺序和事实保真需要人工判断，不能设置成无条件失败规则。批量修改前识别 Markdown 与机器可读内容，修改后复核差异。
