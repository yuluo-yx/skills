## 规则调整

- 保留简短问答和单句翻译的触发边界；明确调用本规范时可处理相关界面文案。
- 将「材料不完整也必须交付完整稿」改为整理已确认内容、具体说明缺口，避免补造事实。
- 区分校对与重写，审阅默认交付问题与建议；用户同时授权修复时可修改文件。
- 默认使用 `「」`、`『』` 和 `……`，中文与英文、数字留一个半角空格；目标项目约定和固定引用可以覆盖。
- 取消固定句长和屏幕行数门槛，采用中文 Markdown 一段一行；保留必要条件、否定关系与结构换行。
- 千位分隔仅用于适用的正文数值，不修改年份、端口、代码或标识符；不根据含糊倍数自行推断百分比。
- 保留目标项目自己的术语和品牌规范，不将技能内示例作为项目覆盖规则。

这些默认规则直接替换原有写作默认值，无数据迁移。旧调用名 `$tech-doc-style-chinese` 改为 `$chinese-document-writing`；旧的 GitHub 五 PR 技能独立卸载，没有合并其行为。
