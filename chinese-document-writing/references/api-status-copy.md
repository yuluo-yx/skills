# API 状态与错误文案

撰写、翻译或审阅 API 参数、状态标签、错误码和技术产品提示时读取。先确认实际语义，区分 HTTP 状态、业务状态、任务状态与界面提示。以下中文只是选择示例，不是枚举转换表。

## 状态选择

| 原词 | 根据实际语义选择 | 避免的误判 |
| --- | --- | --- |
| `Success` | 请求成功、已处理、已完成 | 请求成功不一定表示后台任务完成。 |
| `Accepted` | 已受理、已接收，等待处理 | 不写成已完成。 |
| `Pending` | 待处理、待确认；已开始处理时可用处理中 | 不猜测任务是否已经开始。 |
| `Invalid` | 无效、格式有误、校验未通过 | 不默认翻译成非法。 |
| `Available` | 可访问、可使用、可获取；表示开通状态时用已开通 | 不补造已开通或授权的含义。 |
| `Unsupported` | 不支持该类型、当前不支持 | 无路线图依据时不承诺未来支持。 |
| `Unauthorized` | 缺少认证信息、认证未通过；确因登录状态时用未登录 | 不机械翻译成未授权。 |
| `Forbidden` | 无权限访问、当前不允许访问 | 不将权限或策略拒绝等同于未登录。 |
| `Not Found` | 未找到对应资源或数据 | 不补充资源已删除等未知原因。 |
| `Conflict` | 状态冲突、请求与当前状态冲突 | 不猜测冲突对象。 |
| `Bad Request` | 请求参数有误、请求格式有误 | 按实际错误定位，不笼统归因。 |
| `Expired` / `Missing` | 已过期 / 缺少、未提供 | 不省略受影响对象。 |
| `Completed` / `Failed` / `Timeout` | 已完成 / 处理失败 / 请求或处理超时 | 不混淆请求与任务阶段。 |

状态码、枚举值、字段名和响应原文保持原样；只编辑说明文字和已授权的展示文案。

## 参数说明

每个参数写清有来源依据的类型、格式、是否必填、单位、默认值、允许范围、缺省行为和依赖或互斥关系。「未提供时采用默认值」与「提供空值」不能混写。

不要用「正常值」「根据情况填写」代替具体约束。资料缺失时说明缺口，不自行补充默认值、重试策略或状态码。请求方法、路径、字段和值使用代码环境保护。

## 错误与界面提示

按需要说明发生了什么、影响哪个对象、可能原因、可执行的恢复操作，以及仍失败时需要的诊断信息。原因和恢复方式必须有依据；不承诺来源没有提供的恢复时间。

按钮说明动作与目标；空状态区分无数据、尚未创建、无权限和加载失败。危险操作说明对象、后果和可撤销性。代码中的错误字符串和响应原文保持英文与原样，中文解释写在正文中。
