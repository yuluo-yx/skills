# 受控中文技术写作

完整应用于操作手册、安装部署、故障排查、运维 Runbook、安全说明和多步骤 API 流程。概念说明、FAQ 和发布说明只选择适用规则；不机械改写品牌文案、叙事文本、法律原文、固定引用和短按钮标签。

本模块通过 Fenng 的规范借鉴 ASD-STE100 的受控语言思路，仅采用术语一致、动作明确和条件先行等方法。不移植英语词典、词性或句长规则，不宣称中文文档符合或通过 ASD-STE100 认证。

## 步骤规则

- 一个步骤包含一个主要动作，明确动作对象；有先后依赖的动作拆成编号步骤，同时完成或不可分的动作可以留在同一步。
- 条件先于动作，警告先于风险步骤；条件较多时单列前置条件，不把关键限制藏在句末括号中。
- 可能出现责任歧义时写明执行者，区分人工操作与系统自动行为。
- 写出有来源依据的预期结果、失败时的停止条件和恢复方式；缺失时明确说明，不自创命令、阈值、重试次数或恢复步骤。
- 保持否定范围、因果关系和确定程度，不为追求短句拆散必要的条件或禁止关系。

组织顺序通常为：前置条件、风险与限制、编号动作及预期结果、失败时停止条件与恢复方式。按实际材料取舍，不强制每篇文档出现全部章节。

## 故障排查

先描述可观察的现象和需要收集的日志、状态或错误码，再安排低风险、可逆且能验证假设的检查。每项检查给出判断依据，只有证据充分时才将原因写成结论。

将现象、可能原因、检查操作和结果分开。恢复操作应包含已知的验证方式和停止条件；「可能是网络问题」不能改写为「网络故障导致」。

## 改写示例与检查点

| 原文 | 可接受的改写 | 复核重点 |
| --- | --- | --- |
| 安装前确认服务器能够访问更新地址，然后运行安装命令。 | 先确认服务器能够访问更新地址，再运行安装命令。 | 条件先行，不补造地址或命令。 |
| 选择保存以后系统会写入配置并重新加载服务。 | 选择「保存」。系统随后写入配置并重新加载服务。 | 区分人工动作和系统行为。 |
| 如果设备温度超过允许范围，不要继续启动设备。 | 如果设备温度超过允许范围，不要启动设备。 | 保留条件和禁止关系，不补温度阈值。 |
| 请求失败时最多重试 3 次，每次间隔 5 秒。 | 请求失败时，最多重试 3 次。每次重试间隔 5 秒。 | 保留次数、间隔和触发条件。 |
| 页面无法打开时可能是网络问题，可以先检查浏览器是否能够访问其他站点。 | 页面无法打开时，先检查浏览器能否访问其他站点。网络异常是可能原因之一。 | 不将假设改成确定原因。 |
| 系统通常会在任务完成后发送通知。 | 系统通常在任务完成后发送通知。 | 保留「通常」，不升级为保证。 |
| 平台提供任务创建、状态查询和结果下载能力。 | 保持原文。 | 已经清晰时不为制造差异改写。 |

## 验证边界

对照来源复核事实、对象、数值、单位、条件、否定和确定程度。自动工具可以检查明确错字和术语，不能代替语义判断；句长、被动表达、代词和多个动作不构成自动失败条件。

ASD-STE100 背景见[官方说明](https://www.asd-ste100.org/about_STE.html)。本技能采用范围以[来源说明](sources.md)为准。
